Doc Detective can capture a screenshot at any point in a test. This guide is the entry point to the Screenshots section. It covers a single capture: the full viewport, a cropped element, or an element with padding. The section's other guides cover three related capabilities. [Detect visual regressions](/docs/test-docs/screenshot-visual-regression) compares a capture against a reference image. [Capture screenshots automatically](/docs/test-docs/automatic-screenshots) fires after every step. [Annotate screenshots](/docs/test-docs/annotate-screenshots) marks up an image. Look up every field in the [`screenshot`](/docs/actions/screenshot) action reference and the generated [`screenshot`](/reference/schemas/screenshot) schema. Unlike recording, screenshots capture fine in a headless or CI context.

## Before you begin

Make sure you have the following:

- [Doc Detective installed](/docs/get-started/installation).
- A page or site to capture. The examples below capture a local page.
- A directory where you can create a `.spec.json` file.

The steps in this guide work the same in every authoring style. Write them in a standalone `.spec.json`, [inline in a doc source file](/docs/test-docs/inline), or let Doc Detective [detect them from prose](/docs/test-docs/detected).

## Capture a screenshot

The `screenshot` action takes three shapes, from simplest to most controlled.

Set `screenshot: true` to capture the full viewport with default settings:

{/* test {"testId":"capture-guide-boolean","detectSteps":false} */}

```json title="capture.spec.json"
{
  "tests": [
    {
      "steps": [
        {
          "description": "Capture the full viewport.",
          "screenshot": true
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"capture-guide-boolean-goto","description":"Open the local test server","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"capture-guide-boolean-shot","description":"Capture the full viewport, directed at a gitignored output folder instead of the default path","screenshot":{"path":"guide_boolean.png","directory":"./.dd-output"}} */}
{/* test end */}

Doc Detective saves the image as `<stepId>.png` in [`outputDir`](/reference/schemas/config). `outputDir` defaults to your config file's folder, or to the current folder when you run without a config file. The [GitHub Action](/docs/ci/github-action#find-reports-and-the-run-folder) sets `outputDir` to the runner's temporary directory instead. Set the step's `stepId` to choose the filename. Without one, Doc Detective derives an ID from the test and the step, which stays the same until you change the step.

To choose where the image lands, pass a file path as a string. A relative path resolves against the spec file, or against the current folder when [`relativePathBase`](/reference/schemas/config) is `cwd`:

```json
{
  "description": "Save the capture to a specific file.",
  "screenshot": "./output/login.png"
}
```

By default (`overwrite: "aboveVariation"`), a target path that already holds a file gets compared against the new capture. Doc Detective replaces the file only when the two differ by more than `maxVariation`, which defaults to 5%. Otherwise it leaves the existing file in place. The [Detect visual regressions](/docs/test-docs/screenshot-visual-regression) section covers this behavior in full. Set `"overwrite": "true"` to always replace the file. Set `"overwrite": "false"` to keep the existing file and skip the capture, which reports `SKIPPED`.

For more control, use the object form. Set `crop` to a CSS selector to capture only that element:

{/* test {"testId":"capture-guide-crop","detectSteps":false} */}

```json
{
  "description": "Capture only the login form.",
  "screenshot": {
    "path": "./output/login.png",
    "crop": "#login-form"
  }
}
```

{/* step {"stepId":"capture-guide-crop-goto","description":"Open the local test server","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"capture-guide-crop-shot","description":"Capture only the buttons section (a selector that fits the viewport), directed at a gitignored output folder","screenshot":{"path":"guide_crop.png","directory":"./.dd-output","crop":"#buttons"}} */}
{/* test end */}

`crop` accepts the same selector grammar as `find`, meaning a [CSS](/docs/selectors/css) or [XPath](/docs/selectors/xpath) selector. To disambiguate a selector by its visible text or add breathing room, use the object form of `crop`:

```json
{
  "description": "Capture the Submit button with padding.",
  "screenshot": {
    "path": "./output/submit.png",
    "crop": {
      "elementText": "Submit",
      "padding": 10
    }
  }
}
```

`padding` accepts a single number for all four sides, or an object `{ "top": …, "right": …, "bottom": …, "left": … }` to pad each side independently. For the full list of fields, see the [`screenshot`](/docs/actions/screenshot) action reference and the generated [`screenshot`](/reference/schemas/screenshot) schema.

## Capture dark-mode and localized screenshots

To screenshot a page in dark mode, another language, or at a fixed date, set emulation keys on the context's browser. Each variant gets its own test, with its own `runOn` and its own screenshot `path`.

{/* test {"testId":"capture-guide-dark","detectSteps":false,"runOn":[{"platforms":["windows","mac","linux"],"browsers":{"name":"chrome","headless":true,"colorScheme":"dark","locale":"de-DE"}}]} */}

```json
{
  "testId": "billing-dark-de",
  "runOn": [
    {
      "browsers": {
        "name": "chrome",
        "colorScheme": "dark",
        "locale": "de-DE",
        "timezone": "Europe/Berlin",
        "clock": "2026-12-03T09:00:00Z"
      }
    }
  ],
  "steps": [
    { "goTo": "https://example.com/billing" },
    { "screenshot": "billing-dark-de.png" }
  ]
}
```

{/* step {"stepId":"capture-guide-dark-goto","description":"Open the local test server","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"capture-guide-dark-check","description":"The page sees dark mode and German","runBrowserScript":{"script":"return matchMedia('(prefers-color-scheme: dark)').matches + ' ' + navigator.language;","output":"/^true de-DE$/"}} */}
{/* step {"stepId":"capture-guide-dark-shot","description":"Capture the dark, German page to a gitignored output folder","screenshot":{"path":"guide_dark_de.png","directory":"./.dd-output"}} */}
{/* test end */}

| Key | What the page sees |
|---|---|
| `colorScheme` | `prefers-color-scheme`: `light` or `dark`. |
| `locale` | `navigator.language`, `Intl` formatting, and the `Accept-Language` header. |
| `timezone` | The IANA time zone that `Date` and `Intl` use. |
| `deviceScaleFactor` | `devicePixelRatio`, from 0.5 to 4. Screenshots come out at that pixel density. |
| `reducedMotion` | `prefers-reduced-motion`: `reduce` or `no-preference`. |
| `clock` | `Date.now()` and `new Date()` stay at this ISO 8601 instant. |

Not every browser can set every key:

| Key | Chrome | Firefox | Safari |
|---|---|---|---|
| `colorScheme` | Yes | Yes | Not supported |
| `locale` | Yes | Yes | Not supported |
| `timezone` | Yes | Not supported | Not supported |
| `deviceScaleFactor` | Yes | Yes | Not supported |
| `reducedMotion` | Yes | Yes | Not supported |
| `clock` | Yes | Not supported | Not supported |

A context that asks for a key its browser can't set reports `SKIPPED`. Doc Detective never runs it without the emulation, because a light-mode capture in a dark-mode test would replace your reference image.

```text
Skipped: `safari` can't set `colorScheme`.
```

For every browser key, see [Page emulation](/docs/test-docs/platforms-and-browsers#page-emulation).

## Show stable data in screenshots

Pages often show data that changes, such as "Next invoice: 3 December" or an account balance. A screenshot of that data differs on every run. To keep it the same, answer the request behind it with [`mockRequest`](/docs/actions/mockrequest) before the page loads:

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Answer invoice requests with a fixed date.",
          "mockRequest": {
            "url": "**/api/invoices*",
            "response": { "body": { "next": "2026-12-03" } }
          }
        },
        {
          "goTo": "https://example.com/billing"
        },
        {
          "screenshot": "./output/billing.png"
        }
      ]
    }
  ]
}
```

Put the `mockRequest` step before the `goTo` step, so the page's first request already gets the fixed data. The mock lasts until the test ends.

`mockRequest` runs in Chrome only. In Firefox and Safari, the step reports `SKIPPED` and the page loads its live data.

## Verify it works

- A step that captured an image reports `PASS`.
- When the target path already holds a file and you set `"overwrite": "false"`, the step keeps the existing file and reports `SKIPPED`.

Captures land in the run's output directory and the per-run artifact tree. To see where they land and how to consume them in CI, see [Reporters and artifacts](/docs/ci/reporters-and-artifacts).
