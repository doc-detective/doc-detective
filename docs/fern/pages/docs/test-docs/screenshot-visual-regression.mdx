---
title: Detect visual regressions in screenshots
description: Compare a screenshot capture against a committed reference image to catch visual drift.
---

Turn a screenshot into a regression test by comparing each capture against a saved reference image. When the two drift apart by more than a threshold you set, Doc Detective flags it for review. New to capturing screenshots? Start with [Capture screenshots](/docs/test-docs/capture-screenshots-guide). The comparison runs fine in a headless or CI context.

## Before you begin

Make sure you have the following:

- [Doc Detective installed](/docs/get-started/installation).
- A page or site to capture. The examples below capture a local page.
- A directory where you can create a `.spec.json` file.
- A base `screenshot` step to build on. See [Capture screenshots](/docs/test-docs/capture-screenshots-guide).
- A committed reference image at `path` (the first run seeds it).

The steps in this guide work the same in every authoring style. Write them in a standalone `.spec.json`, [inline in a doc source file](/docs/test-docs/inline), or let Doc Detective [detect them from prose](/docs/test-docs/detected).

## Detect visual regressions

A screenshot becomes a regression test when you compare it against a saved reference image.

Set `maxVariation` to a value from `0` to `1` to enable comparison. It's the maximum acceptable fractional difference between the new capture and the reference at `path`. A difference beyond the threshold returns `WARNING` rather than `FAIL`, because visual drift is a signal to review rather than a hard break:

{/* test {"testId":"capture-guide-regression","detectSteps":false} */}

```json
{
  "description": "Compare against the committed reference image.",
  "screenshot": {
    "path": "./reference/home.png",
    "maxVariation": 0.05,
    "overwrite": "aboveVariation"
  }
}
```

{/* step {"stepId":"capture-guide-regression-goto","description":"Open the local test server","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"capture-guide-regression-shot","description":"Capture with a comparison threshold, directed at a fresh gitignored path so the run seeds the reference and passes","screenshot":{"path":"guide_regression.png","directory":"./.dd-output","maxVariation":0.05,"overwrite":"aboveVariation"}} */}
{/* test end */}

`overwrite` controls when Doc Detective replaces the reference image with the new capture:

- `"false"`: never overwrite.
- `"true"`: always overwrite.
- `"aboveVariation"` (default): overwrite only when the difference exceeds `maxVariation`.

When a comparison runs, the step exposes `$$variation` (the fractional difference) and `$$aspectRatioMatch` (whether the two images share an aspect ratio). Capture either with the step-level `variables` object. For the full list of outputs, see [Visual regression testing](/docs/actions/screenshot) and the [`screenshot`](/reference/schemas/screenshot) schema.

### Reference images in cloud storage

`path` can be an `http(s)://` URL that ends in `.png`, so a team can keep reference images in cloud storage like S3. Signed-URL query strings are fine. Doc Detective downloads the remote image once per run and uses it as a read-only reference. It writes the new capture for inspection to the context's `screenshots/` folder in the [run folder](/docs/ci/reporters-and-artifacts#step-5-collect-the-run-folder-and-artifacts), even when `runFolder` isn't one of your reporters. It ignores `overwrite`, because it never mutates remote storage. In the following example, the new file is `<stepId>_<timestamp>_home.png`:

```json
{
  "description": "Compare against a reference image in S3.",
  "screenshot": {
    "path": "https://my-bucket.s3.amazonaws.com/reference-images/home.png",
    "maxVariation": 0.05
  }
}
```

The reference URL can also be on a local development server or a private network, such as `http://localhost:8080/home.png`, with no setting. To guard against server-side request forgery (SSRF), Doc Detective refuses a public host's redirect to a private address. That includes loopback and link-local addresses, such as the `169.254.169.254` cloud-metadata endpoint.

## Verify it works

- A comparison that stays within `maxVariation` reports `PASS`.
- A comparison that exceeds `maxVariation` reports `WARNING`, so the run continues while flagging the drift for review.

## Troubleshooting

### Visual comparison never runs

**Cause:** `maxVariation` isn't set, so the step only captures an image without comparing it.

**Solution:** set `maxVariation` to a value from `0` to `1` to enable comparison against the reference at `path`.

### A remote reference URL fails with "Couldn't follow the redirect"

**Cause:** the reference URL is on a public host that redirects to a private, loopback, or link-local address. Doc Detective refuses that hop to guard against SSRF.

**Solution:** point `path` at the final address directly. If you trust the redirect, set the `DOC_DETECTIVE_ALLOW_LOCAL_URLS=1` environment variable.

### A local reference URL fails with "DOC_DETECTIVE_BLOCK_LOCAL_URLS refuses private and loopback addresses"

**Cause:** the runner sets `DOC_DETECTIVE_BLOCK_LOCAL_URLS`, which refuses every private and loopback reference URL. Shared runners set it on purpose.

**Solution:** host the reference image on a public address, or unset `DOC_DETECTIVE_BLOCK_LOCAL_URLS` where you control the runner. See [Refuse local URLs on shared runners](/docs/ci/docker-and-headless#refuse-local-urls-on-shared-runners).
