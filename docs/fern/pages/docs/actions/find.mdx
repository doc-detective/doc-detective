---
title: find
description: Locate and interact with an element on the page.
---


The `find` action locates an element in the current interface based on its display text or a CSS/XPath selector. After finding the element, you can optionally interact with it, such as clicking it or typing into it.

If multiple elements match the specified criteria, the step operates on the first matched element. Ensure your criteria uniquely identify the target element.

You can specify the target element directly using a string (for basic text or selector lookup) or use an object for more detailed options and interactions:

- **String Shorthand:** Provide the display text or CSS/XPath selector directly as the value for the `find` key. If elements are found by both text and selector, the element found by matching text is used.
  - Example: `"find": "Login"` or `"find": "#username"`.
- **Object Format:** Use an object with the following properties:
  - `elementText`: (Optional) The display text of the element to find. If combined with other element-finding fields, the element must match all of them. See [How text matching works](#how-text-matching-works) below.
  - `selector`: (Optional) The [CSS selector](/docs/selectors/css) or [XPath selector](/docs/selectors/xpath) of the element to find. If combined with other element-finding fields, the element must match all of them. *At least one element-finding field (`elementText`, `selector`, `elementId`, `elementTestId`, `elementClass`, `elementAttribute`, or `elementAria`) is required.*
  - `elementId`: (Optional) ID attribute of the element. Supports exact match or a regex pattern using `/pattern/` syntax.
  - `elementTestId`: (Optional) `data-testid` attribute of the element. Supports exact match or a regex pattern using `/pattern/` syntax.
  - `elementClass`: (Optional) Class, or array of classes, the element must have. Each class supports exact match or a `/pattern/` regex. The element must have all specified classes.
  - `elementAttribute`: (Optional) Object of attribute key-value pairs the element must have. Values can be strings (supporting `/pattern/` regex), numbers, or booleans. Boolean `true` matches attribute presence, and `false` matches absence.
  - `elementAria`: (Optional) Computed accessible name of the element per the ARIA specification. Supports exact match or a `/pattern/` regex.
  - `timeout`: (Optional) Maximum duration in milliseconds to wait for the element to exist (default: 5000).
  - `moveTo`: (Optional) Move the cursor to the element. If the element isn't visible, it's scrolled into view (default: `false`). A bare `find` leaves the viewport and cursor where they're already sitting, so set this explicitly when a step should scroll, or when a recording needs the cursor to travel to the element.
  - `click`: (Optional) Click the element after finding it. Can be `true` (for a default left click), `"left"`, `"right"`, `"middle"`, or an object like `{ "button": "right" }` or `{ "duration": 800 }` (a long-press / press-and-hold, in milliseconds).
  - `type`: (Optional) Type keys after finding the element. Requires the element to be made active first (for example, by using `click: true`). Accepts a string or an object like `{ "keys": "my text", "inputDelay": 100 }`. See [`type`](type) for details.
  - `surface`: (Optional) The browser (session, window, or tab) the element lives in, for example `{ "browser": "chrome", "tab": "cart" }` or a named browser `{ "browser": "firefox", "name": "admin" }`, or the [native app surface](/docs/actions/startsurface) it lives in, for example `{ "app": "notepad" }` or a specific app window `{ "app": "notepad", "window": { "title": "/Open/" } }`. Omit to act on the active surface (the most recently opened, focused, or explicitly targeted surface, whether that's a browser tab or an app window). Specifying a surface switches the active surface for the steps that follow. On an app surface, `elementText`, `elementId`, and `elementAria` map to native controls, and `selector` accepts a native locator (XPath or a `~`-prefixed accessibility ID) instead of a CSS selector. See [Test across multiple tabs, windows, and browsers](/docs/test-docs/multiple-tabs-and-windows), [Target an app surface](/docs/actions/startsurface#target-an-app-surface), and [App windows](#app-windows) below.

## How text matching works

`elementText` (and the string shorthand's text form) matches an element's
**full visible text** with whitespace normalized. Doc Detective trims leading and
trailing whitespace and collapses internal runs of spaces, tabs, and newlines to a
single space. Two consequences follow from this:

- **Framework-rendered text just works.** Frameworks like React and Svelte often
  split an element's text across several DOM text nodes (sometimes with an empty
  leading node). Because the match uses the element's whole text, a heading like
  `Garden companion API` matches even when it isn't a single, tidy text node, and
  the result stays the same on Chrome and Firefox no matter how each browser's
  driver reports whitespace.
- **It's a whole-element match, not a substring.** `elementText` matches an element
  whose *entire* normalized text equals your string, so a broad `selector` like
  `body` combined with `elementText` won't match (the body's text is the whole
  page). Target a tighter element, or match a substring with
  a regular expression by wrapping the value in slashes: `"elementText": "/Garden companion API/"`.

## App windows

On Windows and macOS app surfaces, `window` selects which of the app's windows the step acts on—dialogs and secondary document windows included:

- `"window": { "title": "Create New Data Source" }` selects by title; wrap the value in slashes for a regex (`"/Data Source/"`).
- `"window": -1` selects the newest window (typically a dialog the app just opened).
- A plain string or `{ "name": … }` matches the window title exactly.
- On macOS, a non-negative `"window": 2` selects by position; on Windows, positional indexes aren't supported (select by title or `-1` instead).

Window selection is **sticky**: later steps on the same app surface act in the selected window until another selector changes it. [`click`](click), [`type`](type), [`screenshot`](screenshot), [`record`](record), [`swipe`](swipe), and [`closeSurface`](closeSurface) all accept the same selector. Android and iOS app surfaces are single-window—a `window` selector there fails with guidance to omit it.

On Windows, resolving a selector probes the app's candidate windows to read their titles, which can briefly bring each probed window to the foreground. This matters for recordings: if a `record` is running, a probe can flash another window into a frame or two of the capture. Select the window *before* starting the recording (selection is sticky) to avoid it.

**Mobile app surfaces auto-scroll:** on an Android or iOS app surface, if the element isn't on screen, `find` scrolls toward content further down the list (up to 5 scroll steps, within `timeout`) before giving up—matching how browser `find` scrolls elements into view. Because [`click`](click) and element-targeted [`type`](type) locate elements the same way, they inherit this. If you need a different gesture (sideways, or a precise drag), use [`swipe`](swipe).

**Setting Variables:** to capture a found element's attributes into variables for later steps, use the step-level `variables` object. You can assign values based on the element using expressions like `$$element.text`.

**Outputs:** the action also exposes `outputs.found`, a boolean indicating whether an element matching your criteria was located. To capture it for later steps, use the step-level `variables` object with the expression `$$found`.

> For comprehensive options, see the [`find`](/reference/schemas/find) reference.

## Examples

Here are a few ways you might use the `find` action:

### Find an element by its text (string shorthand)

{/* test {"testId":"find-by-text","detectSteps":false} */}

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find the login button by its text.",
          "find": "Login"
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"goto-find-text","description":"Open the test page","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"find-text","description":"Find a button by its display text","find":"Standard Button"} */}
{/* test end */}

### Find by ID, test ID, or accessible name

When an element has no stable text, or a selector would be brittle, target it by its `id` attribute (`elementId`), its `data-testid` (`elementTestId`), or its computed accessible name (`elementAria`). The accessible name is the one your browser's DevTools accessibility panel reports for the element. Each takes an exact value or a `/regex/` pattern. The example below finds a button by its test ID. The forms `{ "elementId": "submit-button" }` and `{ "elementAria": "Save document button" }` work the same way.

{/* test {"testId":"find-by-test-id","detectSteps":false} */}

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find the login button by its data-testid.",
          "find": {
            "elementTestId": "login-form-submit"
          }
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"goto-find-testid","description":"Open the enhanced elements test page","goTo":"http://localhost:8092/enhanced-elements.html"} */}
{/* step {"stepId":"find-testid","description":"Find a button by its data-testid","find":{"elementTestId":"login-form-submit"}} */}
{/* test end */}

### Find by class and attribute

Combine `elementClass` with `elementAttribute` to pin down an element by how it's styled and marked up. `elementClass` accepts a single class or an array of classes that must all be present. `elementAttribute` matches attribute values as strings (with `/regex/` support), numbers, or booleans, where `true` requires the attribute to be present and `false` requires it to be absent.

{/* test {"testId":"find-by-class-attribute","detectSteps":false} */}

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find a button that has the btn class and a data-count of 5.",
          "find": {
            "elementClass": "btn",
            "elementAttribute": {
              "data-count": 5
            }
          }
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"goto-find-class-attr","description":"Open the enhanced elements test page","goTo":"http://localhost:8092/enhanced-elements.html"} */}
{/* step {"stepId":"find-class-attr","description":"Find a button by class and a numeric attribute","find":{"elementClass":"btn","elementAttribute":{"data-count":5}}} */}
{/* test end */}

### Match an element with a regular expression

`elementText`, `elementId`, `elementTestId`, `elementClass`, `elementAttribute`, and `elementAria` all match a substring by regular expression when you wrap the value in slashes. This is handy for IDs or text that carry a variable part, such as a generated suffix.

{/* test {"testId":"find-by-regex","detectSteps":false} */}

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find a button whose ID follows the submit-<name>-action pattern.",
          "find": {
            "elementId": "/^submit-.*-action$/"
          }
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"goto-find-regex","description":"Open the enhanced elements test page","goTo":"http://localhost:8092/enhanced-elements.html"} */}
{/* step {"stepId":"find-regex","description":"Find a button by an ID regular expression","find":{"elementId":"/^submit-.*-action$/"}} */}
{/* test end */}

### Move the cursor to an element

Set `moveTo` to `true` to move the cursor to the element. If the element isn't visible, Doc Detective scrolls it into view. A bare `find` leaves the viewport and cursor in place, so set `moveTo` when a step should scroll or when a recording needs the cursor to travel.

{/* test {"testId":"find-move-to","detectSteps":false} */}

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Scroll a lower section into view.",
          "find": {
            "selector": "#tables",
            "moveTo": true
          }
        }
      ]
    }
  ]
}
```

{/* step {"stepId":"goto-find-moveto","description":"Open the test page","goTo":"http://localhost:8092"} */}
{/* step {"stepId":"find-moveto","description":"Scroll the tables section into view","find":{"selector":"#tables","moveTo":true}} */}
{/* test end */}

### Find an element in a specific tab or app surface

Set `surface` to act on an element outside the active surface. A browser reference selects the window or tab the element lives in. An app reference targets a control on a [native app surface](/docs/actions/startsurface). Omit `surface` to act on the active surface.

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find a button in the cart tab.",
          "find": {
            "elementText": "Place order",
            "surface": { "browser": "chrome", "tab": "cart" }
          }
        },
        {
          "description": "Find a native control in an app window.",
          "find": {
            "elementText": "Save",
            "surface": { "app": "notepad", "window": { "title": "/Save As/" } }
          }
        }
      ]
    }
  ]
}
```

### Find using several criteria at once

Element-finding fields combine with AND semantics: the element must match every field you set. This example narrows to a single element by ID, class, and attribute, then moves the cursor to it and clicks. Use `elementAttribute` boolean `true` to require an attribute's presence.

```json
{
  "tests": [
    {
      "steps": [
        {
          "description": "Find one specific enabled button and click it.",
          "find": {
            "elementId": "primary-action",
            "elementClass": ["btn", "btn-primary"],
            "elementAttribute": {
              "data-enabled": "true",
              "disabled": false
            },
            "timeout": 8000,
            "moveTo": true,
            "click": true
          }
        }
      ]
    }
  ]
}
```
