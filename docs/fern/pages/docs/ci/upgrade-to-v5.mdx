---

Doc Detective 5 makes a failed test fail the run. It also separates results from logs, and it tightens how the CLI reads flags and paths. A green run now means tests ran and passed. This guide lists every breaking change, then what to do about it.

## Before you begin

Decide how to take the exit code change, because it's the one most likely to turn a pipeline red.

1. Run your suite once on version 5 with `--no-exit-on-fail`. The run behaves as it did on version 4, and the job stays green while you read the results:

   ```bash
   npx doc-detective@5 --input ./docs --no-exit-on-fail
   ```

2. Fix or triage the failures the run reports.
3. Remove `--no-exit-on-fail` to turn the gate on.

If you can't move yet, pin version 4. An unpinned `npx doc-detective` resolves to the latest release, so name the major version:

```bash
npx doc-detective@4
```

## Node.js version

**What changed:** Doc Detective 5 needs Node.js 24.15 or later, and it's tested on Node.js 24 and 26. Node.js 22 reaches end of life in April 2027. On an older version, npm prints an `EBADENGINE` warning during install, and the run isn't supported.

**What to do:**

1. Move to Node.js 24.15 or later while you're still on Doc Detective 4, which also runs on it.
2. Upgrade Doc Detective.
3. In CI, set the version explicitly, because GitHub-hosted runners default to Node.js 22:

   ```yaml
   - uses: actions/setup-node@v4
     with:
       node-version: 24
   ```

## Exit codes

**What changed:** Failing tests, empty runs, and invalid specs no longer exit `0`.

| Code | Meaning |
|---|---|
| `0` | No test failed, and at least one passed or warned. |
| `1` | At least one test failed. |
| `2` | Nothing valid was tested. Causes include bad usage, bad config, no tests found, every test skipped, an invalid spec, a declined install, or a crash. |
| `130`, `143` | The run was interrupted by SIGINT or SIGTERM. |

A run where every test skipped exits `2`, because nothing was tested. A repository with only fenced code blocks is an example, because those steps skip unless you pass `--allow-unsafe`.

**What to do:** Remove anything that greps the output or parses results only to decide pass or fail, and let the exit code decide. To keep a job green regardless of failures, pass `--no-exit-on-fail` or set `exitOnFail: false`. That setting turns failed, empty, and all-skipped runs into `0`. Usage and config errors still exit `2`.

If a suite only applies to one platform, limit the job to that platform rather than relaxing it:

```yaml
if: runner.os == 'macOS'
```

## Invalid specs

**What changed:** An invalid spec exits `2` before any test runs. Version 4 warned, skipped that spec, and ran the rest.

**What to do:** Fix the spec the error names. To skip invalid specs and run the valid ones while you clean up, pass `--no-exit-on-fail`.

## Unknown keys in specs and steps

**What changed:** A key Doc Detective doesn't recognize on a spec or step, or in a `click`, `runCode`, `record`, or `dragAndDrop` object, makes the spec invalid. Version 4 ignored those keys, so a typo such as `asertions` silently turned off a check. An invalid inline step, or an invalid step in a `before` or `after` file, also makes its spec invalid. Version 4 dropped the step and kept going.

**What to do:** Run your suite, then fix or remove each key the error names. The error suggests the closest valid key:

```text
tests[0].steps[0]: unknown key 'asertions'. Did you mean assertions?
```

Custom metadata needs to move out of the step. To skip these specs and run the rest while you clean up, pass `--no-exit-on-fail`.

## Unknown keys in custom file types

**What changed:** A custom file type can't have keys Doc Detective doesn't recognize, and neither can its `inlineStatements` or `markup` definitions. One makes the config invalid, and the run exits `2`. Version 4 ignored those keys, so a typo, or a key from an older config format such as `testStartStatementOpen`, silently did nothing. Each `markup` definition also needs `regex` or a [selector](/docs/test-docs/input-formats/selectors) kind, and an action name must be one Doc Detective knows. A file type with `runShell` can't also have `markup` or `inlineStatements`.

**What to do:** Fix or remove each key the error names. Move statement patterns into `inlineStatements`, as `testStart`, `testEnd`, `ignoreStart`, `ignoreEnd`, and `step`. See [Custom input formats](/docs/test-docs/input-formats/custom).

## Checks that used to pass

**What changed:** Some checks passed in version 4 without testing anything. These now fail or stop the run:

| Version 4 | Version 5 |
|---|---|
| A condition with a broken `jq()` query, or one that finds nothing, was true. | It's false. |
| A `jq()` comparison like `jq($$body, ".x") == 1` compared the wrong value. | It compares the query's result. |
| A condition that's only text, such as an unset `$VARIABLE`, was true. | It's false, so an assertion fails and an `if` skips. |
| A broken `jq()` query in step `variables` set the variable to the query's text. | The step fails. |
| `assertions` written as objects, like the ones in a report, never ran. | The step fails. Write assertions as strings. |
| A step with two actions ran only one of them. | The spec is invalid. Split it into two steps. |
| Two tests with the same `testId` merged, or ran under one ID. | The spec is invalid. Give each test its own ID. |
| A test whose `before` or `after` file was missing dropped the whole spec. | The spec is invalid. |

**What to do:** Run your suite and fix what it reports. A newly red step was usually a check that wasn't working.

A command that can't start, for example because its `workingDirectory` doesn't exist, now says so instead of reporting exit code `-2`.

## Test detection reads document structure

**What changed:** Doc Detective parses each file before it detects tests, so it reads structure instead of matching raw text. With step detection on, a default config detects different steps:

- **Newly detected:**
  - AsciiDoc and HTML files detect the same steps as Markdown. Before, they detected only inline statements, so pages in these formats can now produce tests that fail the run.
  - DITA detects `screenshot` steps from `<image outputclass="screenshot">`, and `httpRequest` and `runCode` steps from `<codeblock>` elements. It also reads an `<xref>`'s attributes in any order, so `goTo` and `checkLink` steps come from an `<xref>` whose `href` isn't its first attribute, as in `<xref format="html" href="https://example.com">`.
  - Markdown detects links, images, and bold text written as HTML, such as `<a href>` and `<strong>`, and lowercase JSX tags in `.mdx`. It also detects bold text written as `__text__`, and requests in code blocks inside list items.
  - A request header whose value has spaces, such as `Content-Type: application/json; charset=utf-8`, in an HTTP request code block. Before, a value with a space ended the headers, so that header and the lines after it became part of the body.
  - "Browse to" before a link becomes a `goTo` step in Markdown, AsciiDoc, and HTML, as it already did in DITA.
  - A `test start` statement in a comment, as in `<!-- test start {"testId": "a"} -->`, opens a test.
- **No longer detected:**
  - Statements and steps inside code blocks, inline code, `<pre>`, `<script>`, `<codeblock>`, and AsciiDoc listings. A page that shows a sample test no longer runs it.
  - A `runCode` step from a ` ```json ` code block. The pattern for `js` blocks also matched `json`, so every JSON sample became an unsafe JavaScript step.
  - An AsciiDoc `// (step ...)` comment that doesn't start its line.
  - A comment that only starts with "test", such as `<!-- testing notes: x -->`, which used to open a test.
  - The DITA `<data name="step">{...}</data>` form. Use `<data name="doc-detective" value="step {...}"/>` instead.
  - Duplicate DITA steps. An external `<xref>` after "Navigate to" produced two `goTo` steps and two `checkLink` steps, and now produces one of each.
- **Captured differently:** a `find` or `click` step gets bold text as it renders, so `` **`Save`** `` finds `Save`.
- **Invalid MDX:** an `.mdx` file that isn't valid MDX parses as Markdown, with a warning. Content inside its JSX components isn't detected.

A test without its own `testId` gets a new generated ID when its steps change.

**What to do:**

1. Run your suite with `--dry-run` on version 4 and version 5, and compare the tests each detects.
2. Point `--input` at source files, not generated HTML, where every link and bold phrase becomes a step.
3. To turn off step detection, set `detectSteps: false`. Inline statements still work.
4. If a custom file type extends a built-in with `regex` definitions, they still match raw text, code samples included. To limit one to prose, add `"text": {}` to it. See [Selectors](/docs/test-docs/input-formats/selectors).

## Capitalized typing instructions

**What changed:** With step detection on, a Markdown instruction such as `Type "kittens"` or `Enter "admin"` becomes a `type` step whether or not its verb starts with a capital letter. Version 4 detected only lowercase verbs in Markdown, though the docs described both. A test without its own `testId` gets a new generated ID when it gains a step.

**What to do:** Compare `--dry-run` output from version 4 and version 5 to find the new steps. To keep a sentence from becoming a step, put it between `<!-- test ignore start -->` and `<!-- test ignore end -->`, or set `detectSteps: false`.

## `py` and `js` code fences

**What changed:** `runCode` accepts `py` and `js` as languages, which run as `python` and `javascript`. With step detection on, a Markdown fence tagged ` ```py ` or ` ```js ` now becomes a `runCode` step. Version 4 dropped those steps, and a test whose only step was one of them disappeared. The steps are still unsafe, so they run only with `allowUnsafeSteps`. A test without its own `testId` gets a new generated ID when it gains a step.

**What to do:** If you set `allowUnsafeSteps`, compare `--dry-run` output from version 4 and version 5 to find the new steps. To keep a fence from running, add `testIgnore` after its language, as in ` ```py testIgnore `.

## Logs moved to stderr

**What changed:** stdout carries results only. Logs, warnings, hints, and notices go to stderr. Logs also lose their level labels, such as `(INFO)`, unless you turn on debug output.

**What to do:**

- Update anything that reads logs from stdout, or that matches labels like `(ERROR)`. To collect everything in one stream, redirect with `2>&1`.
- Use `--json` for one JSON document on stdout, or `--plain` for one tab-separated line per test context.
- Use `-d` to bring labels back and add timestamps.
- Expect `-l silent` to silence the summary too. Use `-q` to keep errors and the one-line verdict.

## Summary format

**What changed:** The terminal summary is shorter and ends with a one-line verdict, such as `1 of 1 test passed`. The `See detailed results at` line is gone. Run folder paths now print on stderr as `Run report:` and `Run results:`, relative to the current directory.

**What to do:** Stop parsing the summary. Read the results with `--output`, `--json`, or `--plain` instead. See [the fields you can rely on](/docs/ci/reporters-and-artifacts#rely-on-these-fields). Help text and error messages changed throughout too, so don't match on those either. Use the exit code.

## `--output` is a results file

**What changed:** `--output` and the `output` config key always name the JSON results file. Doc Detective overwrites that file on each run, and `-` writes it to stdout. A folder that exists, or a path ending in a slash, exits `2`. Any other path becomes a file, even with no extension. A new `--output-dir` flag and `outputDir` config key set the folder that holds the run folder and the `html`, `junit`, and `markdown` reports.

**What to do:** Replace folder values, including folders that a run used to create:

```bash
# Version 4
doc-detective --input ./docs --output ./reports

# Version 5
doc-detective --input ./docs --output-dir ./reports
```

## No default results file in the current directory

**What changed:** The default reporters are now `terminal` and `runFolder`. A run no longer leaves `testResults-<timestamp>.json` in the current directory. Results land in `.doc-detective/runs/<runId>/testResults.json` instead.

**What to do:** Replace any `testResults-*.json` glob with a fixed path:

```bash
doc-detective --input ./docs --output results.json
```

The `json` reporter still exists, and it still writes a timestamped file in `outputDir`. The `json` and `html` reporters now name files after the run ID, as in `testResults-2026-11-05T01-02-03-004Z.json`, not epoch milliseconds. The `testResults-*` prefix is unchanged. Skip it when you pass `--output`, or you get both files.

## `--concurrent-runners` needs a value

**What changed:** A bare `--concurrent-runners` exits `2`.

**What to do:** Pass a positive whole number or `auto`:

```bash
doc-detective --concurrent-runners auto
```

## Invalid flag values exit 2

**What changed:** A flag value the CLI can't accept, such as `--browser-fallback nope` or `--concurrent-runners 0`, stops the run with exit code `2`.

**What to do:** Correct the value the error names. Check the allowed values with `doc-detective --help`.

## Flags apply only where they make sense

**What changed:** Each subcommand accepts only its own flags. For example, `doc-detective install status --input ./docs` and `doc-detective install status --yes` both exit `2` with `unknown option`.

**What to do:** Remove flags the error names. Run `doc-detective <command> --help` to see what a command accepts.

## Removed commands and bins

**What changed:** The `doc-detective-lsp` and `doc-detective-runner` bins and the `install-agents` alias are gone.

**What to do:** Use the replacements:

| Removed | Use |
|---|---|
| `doc-detective-lsp` | `doc-detective lsp` |
| `doc-detective-runner` | `doc-detective runner` |
| `doc-detective install-agents` | `doc-detective install agents` |

## `install agents` short flags

**What changed:** `install agents` no longer accepts `-a` or `-s`.

**What to do:** Use `--agent` and `--scope`:

```bash
doc-detective install agents --agent claude --scope project --yes
```

## `--silent` on `install`

**What changed:** `install` subcommands reject `--silent`.

**What to do:** Use `-q` or `--quiet`, or `--log-level silent`.

## Debug environment variables

**What changed:** `DOC_DETECTIVE_DEBUG` no longer replaces the run with a diagnostic dump. It now runs your tests with debug output. `DEBUG` also turns on debug output when it's `1`, `true`, `*`, or a pattern matching `doc-detective`.

**What to do:** Use `doc-detective debug` for the diagnostic dump. If a job sets `DEBUG` for another tool to `*` or `1`, expect Doc Detective's debug output on stderr too.

## `.env` loads automatically

**What changed:** Doc Detective loads a `.env` file from the current directory at startup. Variables already set in the shell win over `.env`.

**What to do:** Check that your project's `.env` is safe to load on every run, or pass `--no-env-file`. If you relied on a `.env` overriding a shell variable, unset the shell variable.

## Cache location

**What changed:** New installs cache browsers and runtime packages in `$XDG_CACHE_HOME/doc-detective`, or `~/.cache/doc-detective` if that isn't set. On Windows, they use `%LOCALAPPDATA%\doc-detective`. An existing `~/.doc-detective` keeps being used, so you don't download everything again.

**What to do:** Update any CI cache path that hard-codes `~/.doc-detective`. Setting `DOC_DETECTIVE_CACHE_DIR` makes the path explicit and overrides all of the defaults.

## Telemetry notice

**What changed:** The [telemetry notice](/legal/telemetry) prints once per machine on stderr, not on every run.

**What to do:** Remove anything that matches the old notice text. The opt-outs are `--no-telemetry`, `DO_NOT_TRACK`, and `telemetry.send: false`.

## JavaScript API

**What changed:** If you import `doc-detective` in code, it now exports only `runTests` and `getRunner`. The `detectTests`, `detectAndResolveTests`, `resolveTests`, `readFile`, and `resolvePaths` exports and the `doc-detective/cli` path are gone. In `doc-detective-common`, the built-in `defaultFileTypes` hold [selector](/docs/test-docs/input-formats/selectors) definitions, so code that reads their `regex` patterns finds none.

**What to do:** To see the tests a run would perform, use `doc-detective --dry-run`. To validate specs or detect tests in a string, use the [`doc-detective-common`](https://www.npmjs.com/package/doc-detective-common) package. Run the CLI as a command, not by importing it.

## Deprecated arguments

These still work, and each prints a warning on stderr. Replace them when you can.

| Deprecated | Replacement |
|---|---|
| `runTests`, `runtests` | `run`, or no command |
| `--logLevel` | `--log-level` |
| `-e`, `--exit-on-fail` | Nothing. Failing the run is now the default, so you can delete the flag. |

## GitHub Action

**What changed:** Action `@v2` runs CLI 5. Its `version` input defaults to `5`, `exit_on_fail` defaults to `true`, and it removes the `ios` input. Exit code `2` always fails the job, whatever `exit_on_fail` says. The moving `@v1` tag stays on CLI 4 and refuses `version` 5 or later.

Action `@v2` also writes the results file, the run folder, and reporter files to the runner's temporary directory, overriding any `outputDir` in your config. It drops the undocumented `issueUrl` output, so read `issue_url` instead.

Two inputs have new names: `integrations` is now `issue_mentions`, and `prompt` is now `issue_prompt`. The old names still work in `@v2`, with a deprecation warning.

Exact pins to v1.6.1 or earlier are the risky case. They default to `version: latest`, so they get CLI 5 with no protection. A failing test then fails the job and skips the results, issue, and pull request steps.

**What to do:**

1. Change the action reference:

   ```yaml
   - uses: doc-detective/github-action@v2
   ```

2. For your first run, set `exit_on_fail: false` while you triage existing failures. Remove it to turn the gate on.
3. If you set `integrations` or `prompt`, rename them to `issue_mentions` and `issue_prompt`. Remove the old names rather than keeping them beside the new ones, because setting both fails the job before the run.
4. If you pin an exact version of v1.6.1 or earlier and can't move to `@v2` yet, set `version: 4` on the step.
5. If a later step reads reports or the run folder from your repository, read them from `${{ runner.temp }}` instead. See [Find reports and the run folder](/docs/ci/github-action#find-reports-and-the-run-folder).

See [Run in CI with the GitHub Action](/docs/ci/github-action) for the full setup.

## Verify your upgrade

1. Confirm the version:

   ```bash
   doc-detective --version
   ```

2. Run your suite and check the exit code:

   ```bash
   doc-detective --input ./docs --output results.json
   echo $?
   ```

   A `1` means tests failed, and `results.json` holds the details. A `2` means nothing valid was tested, and stderr says why.

3. Search your pipelines and scripts for the removed items: `testResults-`, `See detailed results`, `install-agents`, `doc-detective-lsp`, `doc-detective-runner`, and `--output` with a folder.

For every flag, see the [CLI reference](/reference/reference/cli).
