title: Detected tests
description: Automatically generate tests based on your documentation source files.

Doc Detective can automatically generate tests based on your documentation source files and your `fileTypes` configuration. Detected tests are useful for large, complex test suites that you want to keep in sync with your documentation. Step detection is on by default. With no extra configuration, the built-in file types detect steps from links, bold text, images, code blocks, and quoted text after `Type`, `Enter`, or `Press`. They skip code samples. To detect other content, define markup patterns and their actions in the `fileTypes.markup` array of your [config](/reference/schemas/config), as described in [Detect tests with selectors](/docs/test-docs/input-formats/selectors). To turn detection off, set `detectSteps` to `false`.

Detected tests are useful for keeping your tests in sync with your documentation. When you update your documentation, Doc Detective automatically updates the tests based on the new content. Detected tests are generated automatically. You can't edit detected tests directly, but you can update your config or documentation source files to change the tests.

> You can mix detected tests with [inline tests](/docs/test-docs/inline) to declare steps your content might not cover, such starting or stopping a recording.

## Benefits of detected tests

Detected tests provide several advantages:

- **Automatic synchronization**: Tests update automatically when documentation changes
- **Reduced maintenance**: No need to manually update test specifications
- **Consistent coverage**: Ensures all documented procedures are tested
- **Time savings**: Eliminates the need to write many test specifications manually

Combine detected tests with [inline tests](/docs/test-docs/inline) for comprehensive test coverage with minimal manual effort.

## Default markup patterns

Every built-in format (Markdown, HTML, AsciiDoc, and DITA) detects the same steps from links, bold text, images, code blocks, and quoted text after `Type`, `Enter`, or `Press`. [What gets detected](/docs/test-docs/input-formats/overview#what-gets-detected) lists them. Doc Detective parses each file first, so text inside code blocks and inline code never becomes a step.

In Markdown, for example:

- **goToUrl**: `Go to [Page Name](https://example.com)` generates a `goTo` step.
- **checkHyperlink**: Every link to an `http` or `https` URL generates a `checkLink` step.
- **clickOnscreenText**: Bold text after a click verb, such as `Click **Button Name**`, generates a `click` step.
- **findOnscreenText**: All bold text generates a `find` step.
- **screenshotImage**: An image with the `.screenshot` class, such as `![Alt text](image.png){.screenshot}`, generates a `screenshot` step.
- **typeText**: A typing instruction in prose, such as `Type "Hello World"`, generates a `type` step.
- **httpRequestFormat**: A code block tagged `http` that holds a request generates an `httpRequest` step.
- **runCode**: A code block tagged `bash`, `python`, `py`, `javascript`, or `js` generates a `runCode` step.

DITA also uses its semantic elements. `<cmd>Click the <uicontrol>Submit</uicontrol> button</cmd>` generates `click` and `find` steps, and `<cmd>Type <userinput>text</userinput> into the <uicontrol>Field</uicontrol></cmd>` generates a `type` step into that field.

For each format's syntax, see [Markdown](/docs/test-docs/input-formats/markdown), [HTML](/docs/test-docs/input-formats/html), [AsciiDoc](/docs/test-docs/input-formats/asciidoc), and [DITA](/docs/test-docs/input-formats/dita).

## Example with detected tests

With the default configuration, Doc Detective takes the following Markdown and generates tests automatically:

**Markdown:**

```markdown
To get started,

1. Go to [Acme Console](https://console.acme.com).
2. Click **Search**.
3. Type "American Shorthair kittens".

Check out our [documentation](https://docs.example.com) for more information.

![Search results](search-results.png){ .screenshot }
```

**Detected tests:**

```json
{
  "tests": [
    {
      "steps": [
        { "goTo": "https://console.acme.com" },
        { "checkLink": "https://console.acme.com" },
        { "click": "Search" },
        { "find": "Search" },
        { "type": "American Shorthair kittens" },
        { "checkLink": "https://docs.example.com" },
        { "screenshot": "search-results.png" }
      ]
    }
  ]
}
```

## Custom markup patterns

You can extend or override the default patterns by defining custom markup patterns in your configuration:

```json
{
  "fileTypes": [
    {
      "name": "markdown",
      "extensions": ["md", "markdown", "mdx"],
      "markup": [
        {
          "name": "customAction",
          "regex": ["\\b(?:custom)\\b\\s+\\*\\*(.+?)\\*\\*"],
          "actions": [
            {
              "find": {
                "selector": "aria/$1",
                "timeout": 10000
              }
            }
          ]
        }
      ]
    }
  ]
}
```

A `regex` pattern matches the file's raw text, code samples included. To match structure instead, such as bold text outside code, use a [selector](/docs/test-docs/input-formats/selectors).

### Default actions

If you only need to perform basic steps, you can define actions using a shorthand of only specifying the action name. Doc Detective uses default actions. It substitutes the first capture group from the regex pattern into the most common location for the action. When there are no capture groups, it substitutes the entire match.

The default actions are as follows:

#### `checkLink`

Check that the match returns a valid status code.

```json
{ "checkLink": "$1" }
```

### `click`

Click or tap the match.

```json
{ "click": "$1" }
```

#### `goTo`

Open the match as a URL in a browser.

```json
{ "goTo": "$1" }
```

#### `find`

Find an element on the current page that has an ARIA label that equals the match.

```json
{ "find": "$1" }
```

#### `screenshot`

Save a screenshot to a path equalling the match.

```json
{ "screenshot": "$1" }
```

#### `type`

Type the match into the current page.

```json
{ "type": "$1" }
```

#### `httpRequest`

Make an GET request to the match.

```json
{ "httpRequest": "$1" }
```

#### `runShell`

Run the match as a shell command.

```json
{ "runShell": "$1" }
```

#### `record`

Start recording a video to a path equalling the match.

```json
{ "record": "$1" }
```

#### `stopRecord`

Stop recording a video.

```json
{ "stopRecord": true }
```

#### `wait`

Wait for the specified duration.

```json
{ "wait": "$1" }
```

#### `loadVariables`

Load environment variables from an `.env` file, where the path is the match.

```json
{ "loadVariables": "$1" }
```

#### `saveCookie`

Save a browser cookie by name to a default location.

```json
{ "saveCookie": "$1" }
```

#### `loadCookie`

Load a browser cookie by name from a default location.

```json
{ "loadCookie": "$1" }
```
