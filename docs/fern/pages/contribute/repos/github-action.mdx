[`github-action`](https://github.com/doc-detective/github-action) is a TypeScript-based GitHub Action that runs Doc Detective in GitHub workflows. Doc Detective can run in any CI/CD environment, but this GitHub Action simplifies running it in GitHub workflows. It also provides a `results` output, a JSON string you pass through `fromJSON()` to read in later steps. It offers handy features too, like creating GitHub issues for failed tests.

This repo depends on [`doc-detective`](doc-detective) for performing the tests.

## Issue notifications

The GitHub Action can automatically create GitHub issues when tests fail. Set `create_issue_on_fail` to `true` to enable this.

### Basic issue configuration

- `create_issue_on_fail`: Creates a GitHub issue when any test fails.
- `issue_title`: Title of the created issue. Default: `"Doc Detective Failure"`.
- `issue_body`: Body of the issue. Supports these variables:
  - `$RUN_URL`: URL of the workflow run that created the issue.
  - `$RESULTS`: Test results as a JSON code block.
  - `$PROMPT`: The prompt text (see below).
- `issue_labels`: Comma-separated list of labels to apply.
- `issue_assignees`: Comma-separated list of GitHub usernames to assign.

### AI issue mentions

Mention AI assistants in created issues to help investigate and fix failures faster. Use `issue_mentions` to specify which assistants to mention.

- `issue_mentions`: Comma-separated list of assistants to mention. Supported values:
  - `doc-sentinel`: Adds the line `/cc @reem-sab`, without the prompt
  - `promptless`: Mentions `@promptless` with the prompt
  - `dosu`: Mentions `@dosu` with the prompt
  - `claude`: Mentions `@claude` with the prompt
  - `cursor`: Mentions `@cursor` with the prompt
  - `opencode`: Uses the `/opencode` command with the prompt
  - `copilot`: Auto-assigns the issue to Copilot (instead of adding to the accordion)
  
  Mentions (except `copilot`) appear in a collapsible section in the issue body. The action ignores unsupported values and logs a warning.

- `issue_prompt`: Text that follows each mention. You can also use `$PROMPT` in your custom `issue_body` template. Default: `"Investigate potential causes of the failures reported in this Doc Detective test output and suggest fixes."`.

### Example

```yaml
- uses: doc-detective/github-action@v2
  with:
    input: ./docs
    create_issue_on_fail: true
    token: ${{ secrets.DOC_DETECTIVE_ISSUE_TOKEN }}
    issue_mentions: claude,copilot
    issue_prompt: "Analyze these test failures and suggest documentation fixes"
```

Action `@v2` renamed `integrations` to `issue_mentions` and `prompt` to `issue_prompt`. The old names still work as deprecated aliases that log a warning, and setting both an old and a new name fails the job. For the user-facing guide, see [AI issue mentions](/docs/ci/issue-mentions).

`claude` needs `token`, because GitHub doesn't start Claude Code's workflow for an issue that the default `GITHUB_TOKEN` opens. See [Hand off test failures to an AI agent](/ai/ai-agents/hand-off-failures).
