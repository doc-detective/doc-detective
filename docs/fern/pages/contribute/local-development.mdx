Set up a local development environment to preview your changes, work across multiple files, and test documentation builds.

## When to use local development

Use local development when:

- Making changes across multiple files
- Writing substantial new content
- Adding complex formatting or components
- Testing documentation builds
- Running automated checks before submitting

For quick fixes (typos, small wording changes), use the [browser-based workflow](quick-start) instead.

## System requirements

- [Node.js](https://nodejs.org/) version 22 or later
- [Git](https://git-scm.com/) for version control
- [VS Code](https://code.visualstudio.com/) recommended as code editor
- [Vale](https://vale.sh/) (optional) for style checking
- Command line access (Terminal)

### Check your Node.js version

```bash
node --version
```

Should show `v22.0.0` or higher.

## Fork and clone the repository

The docs live in the `docs/` directory of the [`doc-detective`](https://github.com/doc-detective/doc-detective) repo, alongside the code they describe.

### 1. Fork the repository

1. Go to [https://github.com/doc-detective/doc-detective](https://github.com/doc-detective/doc-detective).
2. Click **Fork** in the top right.
3. Select your GitHub account as the destination.

### 2. Clone your fork

```bash
# Replace YOUR-USERNAME with your GitHub username
git clone https://github.com/YOUR-USERNAME/doc-detective.git
cd doc-detective
```

### 3. Add upstream remote

This lets you sync with the main repository:

```bash
git remote add upstream https://github.com/doc-detective/doc-detective.git
```

Verify remotes:

```bash
git remote -v
```

Should show:

```
origin    https://github.com/YOUR-USERNAME/doc-detective.git (fetch)
origin    https://github.com/YOUR-USERNAME/doc-detective.git (push)
upstream  https://github.com/doc-detective/doc-detective.git (fetch)
upstream  https://github.com/doc-detective/doc-detective.git (push)
```

## Install dependencies

Install the docs dependencies from the `docs/` directory:

```bash
cd docs
npm install
```

## Working locally

Start the development server:

```bash
npm run start
```

The documentation site opens at `http://localhost:3000` with live reload. Changes appear instantly as you edit files.

To make changes,

1. **Create a branch**:

   ```bash
   git checkout -b your-feature-name
   ```

   Use descriptive branch names: `add-tutorial-X`, `fix-broken-links`, `document-feature-Y`

2. **Edit files**:

   - Documentation pages are in `fern/pages/`
   - Edit in your preferred code editor
   - Save and see changes live at `http://localhost:3000`

3. **Commit regularly**:
   ```bash
   git add .
   git commit -m "Descriptive commit message"
   ```

### Check the site

Before submitting, validate the Fern configuration and pages from the `docs/` directory:

```bash
npx fern check
```

Fix any errors before submitting your PR. To preview the site, use the local server from `npm run start`. A pull request from a branch in the `doc-detective/doc-detective` repo also gets a bot comment linking to a hosted preview. Pull requests from forks don't, because the preview needs a repository secret.

## Run automated checks

### Style checking with Vale

Vale enforces the documentation style guide. Run it from the `docs/` directory, where it finds its `.vale.ini` configuration.

```bash
# Check all documentation except the generated schema reference pages, which CI also skips
vale '--glob=!fern/pages/reference/schemas/**' fern/pages/

# Check specific file
vale fern/pages/path/to/file.mdx
```

**Interpret results:**

- **Error**: Should be fixed
- **Warning**: Strongly consider fixing
- **Suggestion**: Optional improvement

Don't worry about fixing every suggestion. Reviewers use their judgment during reviews.

## Common tasks

### Add a new documentation page

1. Create the file:

   ```bash
   touch fern/pages/docs/category/your-page.mdx
   ```

2. Add front matter:

   ```markdown
   ---
   title: Your Page Title
   description: Brief description for search engines
   sidebar-title: Sidebar Text
   sidebar_position: 3
   ---

   Content goes here...
   ```

3. Update the navigation (if needed):

   Edit `fern/docs.yml` to add your page to navigation.

### Add images

1. Place images in `static/img/`:

   ```bash
   cp screenshot.png static/img/features/
   ```

2. Reference images in docs with paths relative to `static`:
   ```markdown
   ![Description of image](/img/features/screenshot.png)
   ```

### Add code examples

Use fenced code blocks with language identifiers:

````markdown
```json title="example.spec.json"
{
  "tests": []
}
```
````

## Troubleshooting

### Port 3000 already in use

Stop other development servers or use a different port:

```bash
npm run start -- --port 3001
```

### Fern fails with module errors

Reinstall and check again:

```bash
rm -rf node_modules
npm ci
npx fern check
```

### Changes aren't appearing

Hard refresh your browser:

- **Windows/Linux**: `Ctrl+Shift+R`
- **macOS**: `Cmd+Shift+R`

Or restart the dev server:

```bash
# Press Ctrl+C to stop
npm run start
```

### Vale can't find its configuration

Make sure you're running Vale from the `docs/` directory, which holds `.vale.ini`:

```bash
cd /path/to/doc-detective/docs
vale '--glob=!fern/pages/reference/schemas/**' fern/pages/
```

### npm install fails

1. Check Node.js version:

   ```bash
   node --version  # Should be 22 or higher
   ```

   If needed, update [Node.js](https://nodejs.org/).

1. Clear npm cache:

   ```bash
   npm cache clean --force
   npm install
   ```

## Git workflows

### Sync with upstream

Before starting new work, sync with the main repository:

```bash
git checkout main
git fetch upstream
git merge upstream/main
git push origin main
```

### Create a feature branch

Always work on a branch, not `main`:

```bash
git checkout -b descriptive-branch-name
```

### Commit changes

Make small, focused commits:

```bash
git add fern/pages/path/to/changed-file.mdx
git commit -m "Add troubleshooting section for X"
```

### Push changes

```bash
git push origin your-branch-name
```

### Create a pull request (on GitHub)

1. Go to your fork on GitHub.
2. Click **Compare & pull request**.
3. Fill out the PR template.
4. Click **Create pull request**.

See [Standard changes](standard-contributions) or [Substantial changes](substantial-contributions) for PR guidelines.

## Development tips

### Use snippets

Create editor snippets for common patterns:

**VS Code** → Settings → User Snippets → `markdown.json`:

```json
{
  "Doc frontmatter": {
    "prefix": "docfront",
    "body": [
      "---",
      "title: ${1:Title}",
      "description: ${2:Description}",
      "sidebar-title: ${3:Label}",
      "---",
      "",
      "$0"
    ]
  }
}
```

### Watch for common mistakes

- **Wrong file extension**: Use `.mdx`, not `.md`.
- **Missing front matter**: All docs need title, description, etc.
- **Wrong link format**: Use `/docs/path`, not `./path` or `../path`.
- **Unescaped special characters**: Escape `<`, `>`, `{`, `}` in text.

### Use VS Code extensions

Recommended extensions include

- **MDX**: Syntax highlighting for `.mdx` files
- **Vale**: Inline style checking
- **Code Spell Checker**: Catch typos
- **Markdown All in One**: Formatting tools
