Each example on this page shows one documented procedure as prose, detected tests, inline tests, and a standalone spec. For what each tab holds, see [Navigation and interaction](/reference/docs-as-tests/navigation-interaction).

Here, the detected variants run with custom [`fileTypes`](/reference/schemas/config), and each example's config sits above its tabs. The prose, inline, and standalone variants are the same as on any other page. For how selectors and regex definitions work, see [Selectors](/docs/input-formats/selectors) and [Custom input formats](/docs/input-formats/custom).

Custom definitions match what one format writes, so most examples show only the formats their definitions apply to.

## Extend Markdown with your own conventions

This file type uses [`extends`](/reference/schemas/config), `name`, and `extensions` to build on the Markdown and MDX defaults. Its [`markup`](/reference/schemas/markup-definition) uses the `link`, `strong`, `text`, `element`, and `emphasis` selectors with `precededBy`, `excludes`, `captures`, and `regex`, and `element` in its string form. Its [`inlineStatements`](/reference/schemas/config) read statements from comments that start with `dd:`. The steps are [`goTo`](/docs/actions/goto), [`find`](/docs/actions/find), [`click`](/docs/actions/click), [`type`](/docs/actions/type), and [`wait`](/docs/actions/wait).

```json title="doc-detective.json (fileTypes)"
{
  "fileTypes": [
    {
      "name": "markdown-ui",
      "extends": "markdown",
      "extensions": ["md", "mdx"],
      "inlineStatements": {
        "in": [{ "comment": {}, "regex": "^dd:\\s*([\\s\\S]*)$" }]
      },
      "markup": [
        {
          "name": "goToUrl",
          "link": { "url": "^https?://", "precededBy": "\\b[Gg]o to(?: the)?\\s+$", "excludes": "^\\s*$" },
          "captures": ["url", "text"],
          "actions": ["goTo", { "find": "$2" }]
        },
        {
          "name": "clickOnscreenText",
          "strong": { "precededBy": "\\b(?:[Cc]lick|[Ss]elect)\\s+$" },
          "actions": ["click"]
        },
        {
          "name": "findOnscreenText",
          "strong": { "excludes": "^(?:Note|Tip):?$" },
          "actions": ["find"]
        },
        {
          "name": "typeText",
          "text": { "excludes": "^\\s*For example\\b" },
          "regex": "\\b(?:[Pp]ress|[Ee]nter|[Tt]ype)\\b\\s+\"([^\"]+)\"",
          "actions": ["type"]
        },
        {
          "name": "typeKeyboardInput",
          "element": { "tag": ["kbd"], "precededBy": "\\b[Ee]nter\\s+$", "excludes": "^(?:Enter|Tab|Esc|Ctrl|Shift|Alt)\\b" },
          "captures": ["content"],
          "actions": ["type"]
        },
        {
          "name": "waitForUpdate",
          "emphasis": { "precededBy": "\\b[Ww]ait\\s+$", "excludes": "^0 ms$" },
          "regex": "^(\\d+) ms$",
          "actions": ["wait"]
        },
        {
          "name": "findSampleOutput",
          "element": "samp",
          "actions": ["find"]
        }
      ]
    },
    "asciidoc",
    "html",
    "dita",
    "rst"
  ]
}
```

### What detection finds

| Prose | Definition | Detected steps |
|---|---|---|
| `Go to the [Type Echo Test Page](…)` | `goToUrl`, replaced | `goTo` the URL and `find` the link text, then the default `checkLink` |
| `**Note:**` and `**Tip:**` | `findOnscreenText`, replaced | None. `excludes` skips the labels |
| `For example, type "Hi"` | `typeText`, replaced | None. `text.excludes` skips sentences that start with "For example" |
| `Click **Type here:**` | `clickOnscreenText` and `findOnscreenText`, both replaced | `click`, then `find` |
| `Enter <kbd>…</kbd>` | `typeKeyboardInput` | `type` the element's content |
| `Wait _500 ms_` | `waitForUpdate` | `wait` 500 |
| `<samp>Hello, Doc Detective</samp>` | `findSampleOutput` | `find` the sample output |

- With `extends`, a definition whose `name` matches a built-in one replaces it, and the rest of the built-in definitions still run. That's how `goToUrl` changes here, and why the link still gets the default `checkLink`.
- The replaced `clickOnscreenText` clicks only after `Click` or `Select`. The built-in one also clicks after verbs such as `Check` and `Choose`.
- Each `excludes` keeps a look-alike from becoming a step. Here, that's a link with no text, a key name such as `<kbd>Tab</kbd>`, and a zero wait.
- `"element": "samp"` is short for `{ "tag": ["samp"] }`. `<samp>` marks sample output, so finding it checks what the page shows.
- `captures` picks the values for `$1`, `$2`, and so on. An action name, such as `"goTo"`, takes `$1`. An object, such as `{ "find": "$2" }`, is a step template.
- The `dd:` prefix is the custom part of the statements. `inlineStatements` from `extends` still read plain `test` comments, so the inline variants need no custom config.
- In Markdown and MDX, `<kbd>` and `<samp>` are HTML tags, so the `element` selector finds them in both formats.

## Run a script split across code blocks

Each file type extends a built-in format and adds one `codeBlock` definition. It uses `language`, `excludes`, and `batchMatches` to join a tutorial's code blocks into one [`runCode`](/docs/actions/runcode) step.

```json title="doc-detective.json (fileTypes, one entry)"
{
  "extends": "markdown",
  "markup": [
    {
      "name": "runCode",
      "codeBlock": { "language": ["javascript", "js"], "excludes": "^// Don't run" },
      "batchMatches": true,
      "actions": [{ "runCode": { "language": "javascript", "code": "$1" } }]
    }
  ]
}
```

The config repeats this entry with `extends` set to `asciidoc`, `html`, `rst`, and `dita`, because each entry extends one format.

<Markdown src="examples/custom-script-blocks/_variants.mdx" />

### What detection finds

In every format, detection resolves the three code blocks to one `runCode` step:

- `batchMatches` joins the matching blocks, in document order and separated by newlines, into one `$1`. The script runs as one program, so the second block can use `name` from the first.
- `excludes` skips the block that starts with `// Don't run`. Run with the other blocks, it would declare `name` a second time and fail.
- The definition's `name`, `runCode`, replaces the built-in `runCode` definition. The built-in one runs each block as its own step and marks it `unsafe`.
- The inline and standalone variants also set `stdio`, to check what the script prints. A detected step has only what the definition's template sets.

## Mark up controls with attributes

These file types extend HTML and DITA. They use the `link`, `image`, `element`, `comment`, and `text` selectors with `url`, `attributes`, `src`, `precededBy`, `excludes`, `captures`, and `regex`. The HTML type also reads statements from an element's attribute, with an `inlineStatements.in` container and `value`. The steps are [`checkLink`](/docs/actions/checklink), [`goTo`](/docs/actions/goto), [`click`](/docs/actions/click), [`type`](/docs/actions/type), [`wait`](/docs/actions/wait), and [`find`](/docs/actions/find).

```json title="doc-detective.json (fileTypes, HTML entry)"
{
  "extends": "html",
  "inlineStatements": {
    "in": [{ "element": { "tag": ["div"], "attributes": { "data-test": true } }, "value": "attributes.data-test" }]
  },
  "markup": [
    {
      "name": "goToUrl",
      "link": { "url": "^https?://", "precededBy": "\\b[Gg]o to\\s+$" },
      "captures": ["url"],
      "actions": ["goTo"]
    },
    {
      "name": "checkHyperlink",
      "link": { "url": "^https?://", "attributes": { "data-check": true }, "excludes": "^\\s*$" },
      "captures": ["url"],
      "actions": ["checkLink"]
    },
    {
      "name": "checkHostedImage",
      "image": { "src": "^https?://", "attributes": { "class": "(^|\\s)hosted(\\s|$)" }, "precededBy": "(?:^|>)\\s*$", "excludes": "^\\s*$" },
      "captures": ["src"],
      "actions": ["checkLink"]
    },
    {
      "name": "clickUiLabel",
      "element": { "tag": ["span", "ph"], "attributes": { "class": "(^|\\s)ui(\\s|$)" }, "precededBy": "\\b[Cc]lick\\s+$" },
      "actions": ["click"]
    },
    {
      "name": "waitComment",
      "comment": { "excludes": "\\bTODO\\b" },
      "regex": "^\\s*wait (\\d+)\\s*$",
      "actions": ["wait"]
    },
    {
      "name": "findEcho",
      "text": {},
      "regex": "\\bthe page shows (.+?) below the field",
      "actions": [{ "find": { "elementText": "$1", "timeout": 5000 } }]
    }
  ]
}
```

The DITA entry has the same `checkHostedImage`, `clickUiLabel`, `waitComment`, and `findEcho` definitions with `extends` set to `dita`. It has no `inlineStatements`, so DITA keeps its built-in `<data>` statements. DITA has no `link` nodes, so its links keep the built-in `<xref>` definitions.

<Markdown src="examples/custom-html-attributes/_variants.mdx" />

### What detection finds

| Content | Definition | Detected step |
|---|---|---|
| An image with the `hosted` class | `checkHostedImage` | `checkLink` the image's source |
| `Go to <a data-check>` | `goToUrl` and `checkHyperlink`, replaced | `goTo`, then `checkLink` |
| `Go to <xref>` | Default `goToUrl` and `checkHyperlink` | `goTo`, then `checkLink` |
| `Click` and a `ui` label | `clickUiLabel` | `click` the label's text |
| `Type "…"` | Default `typeText` | `type` |
| `<!-- wait 500 -->` | `waitComment` | `wait` 500 |
| `the page shows … below the field` | `findEcho` | `find` with `elementText` and `timeout` |

- One `attributes` pattern matches both formats. DITA's `outputclass` sets `class`, and an `<image>`'s `href` is its `src`.
- The replaced `checkHyperlink` checks only links an author marks with `data-check`, and skips links with no text. `"data-check": true` only requires the attribute.
- The replaced `goToUrl` sits before `checkHyperlink`, so the `goTo` still comes before the `checkLink` for the same link. Your definitions run before the built-in ones, in the order you list them.
- `checkHostedImage` skips decorative images, whose alt text is empty, and images inside a sentence. Its `precededBy` matches only when nothing but a tag comes before the image in its block.
- `waitComment` skips comments that say `TODO`, so a note about a wait to add later doesn't become a step.
- The `wait 500` comment isn't visible to readers, so the detected variants carry it where the prose has nothing. It's the detected counterpart of a `step` statement.
- In HTML, the hidden `<div data-test>` elements hold the `test` and `test end` statements, for sites whose build strips comments.
- These formats leave out Markdown, MDX, AsciiDoc, and reStructuredText. Their links and images don't carry a `class` attribute in the same way, and AsciiDoc and reStructuredText produce no `element` nodes.

## Define a plain-text format

This file type has no `extends`. Its `name` and `extensions` define a format for `.txt` files. Its `inlineStatements` use the regex statement keys `testStart`, `testEnd`, `ignoreStart`, `ignoreEnd`, and `step`, each with one pattern as a string. Its `includeStatements` pattern pulls in a shared file, and its `markup` uses regex definitions. The steps are [`checkLink`](/docs/actions/checklink) and [`httpRequest`](/docs/actions/httprequest).

```json title="doc-detective.json (fileTypes)"
{
  "fileTypes": [
    {
      "name": "plain-text",
      "extensions": ["txt"],
      "inlineStatements": {
        "testStart": "(?:^|\\n)[ \\t]*TEST (\\{.*\\})",
        "testEnd": "(?:^|\\n)[ \\t]*END TEST",
        "ignoreStart": "(?:^|\\n)[ \\t]*IGNORE START",
        "ignoreEnd": "(?:^|\\n)[ \\t]*IGNORE END",
        "step": "(?:^|\\n)[ \\t]*STEP (\\{.*\\})"
      },
      "includeStatements": "^[ \\t]*INCLUDE (\\S+)[ \\t]*$",
      "markup": [
        {
          "name": "checkUrl",
          "regex": ["\\b[Cc]heck that (https?://\\S+) responds\\b"],
          "actions": ["checkLink"]
        },
        {
          "name": "sendRequest",
          "regex": ["\\bSend an? (GET|POST|PUT|PATCH|DELETE) request to (https?://\\S+) with the body (\\{.*\\})\\.(?=\\s|$)"],
          "actions": [{ "httpRequest": { "method": "$1", "url": "$2", "request": { "body": "$3" } } }]
        }
      ]
    },
    "markdown",
    "asciidoc",
    "html",
    "dita",
    "rst"
  ]
}
```

<Markdown src="examples/custom-plain-text/_variants.mdx" />

### What detection finds

- No parser handles `.txt`, so this format can't use selectors. Regex definitions match the file's raw text.
- Regex patterns run without flags, so `^` matches only the start of the file. `(?:^|\n)` matches the start of any line.
- `checkUrl` uses the `checkLink` action name, which takes `$1`. `sendRequest` is a step template with three groups. A request body that's a JSON object becomes an object, not a string.
- The inline and standalone variants also check the response body. A detected step has only what the definition's template sets.
- `INCLUDE prerequisites.txt` pulls in a shared file from the same folder, which holds one line: `Before you start, check that http://localhost:8092/api/users responds.` Doc Detective includes it before it detects steps, so `checkUrl` finds the `checkLink` there. Includes need `resolveIncludes`, which is on by default. `^` and `$` in `includeStatements` match at line boundaries.
- `IGNORE START` and `IGNORE END` wrap the `DELETE` example, so detection skips a request the procedure only describes.
- The inline variant uses the format's own `TEST`, `STEP`, and `END TEST` lines, so it needs this config too. The other examples' inline variants use the built-in statement syntax.

## Keep statements in markup your site keeps

Some publishing pipelines strip HTML comments, so statements in comments never reach the published source. This Markdown file type reads statements from other markup instead. Its regex statement keys, `testStart`, `testEnd`, `ignoreStart`, `ignoreEnd`, and `step`, each take a list of patterns. Its `inlineStatements.in` list has one container of each selector kind: `comment`, `codeBlock`, `link`, `image`, `strong`, `emphasis`, `text`, and `element`. Its `markup` runs code blocks with [`runShell`](/docs/actions/runshell), with `codeBlock` in its string form and with `metaExcludes`. The other steps are [`goTo`](/docs/actions/goto), [`find`](/docs/actions/find), [`click`](/docs/actions/click), [`type`](/docs/actions/type), [`wait`](/docs/actions/wait), and [`checkLink`](/docs/actions/checklink).

```json title="doc-detective.json (fileTypes)"
{
  "fileTypes": [
    {
      "name": "markdown-statements",
      "extends": "markdown",
      "inlineStatements": {
        "testStart": ["<!--\\s*dd-test\\s+(\\{[\\s\\S]*?\\})\\s*-->", "<!--\\s*doc-detective-test\\s+(\\{[\\s\\S]*?\\})\\s*-->"],
        "testEnd": ["<!--\\s*dd-end\\s*-->", "<!--\\s*doc-detective-end\\s*-->"],
        "ignoreStart": ["<!--\\s*dd-skip\\s*-->", "<!--\\s*doc-detective-skip\\s*-->"],
        "ignoreEnd": ["<!--\\s*dd-resume\\s*-->", "<!--\\s*doc-detective-resume\\s*-->"],
        "step": ["<!--\\s*dd-step\\s+(\\{[\\s\\S]*?\\})\\s*-->", "<!--\\s*doc-detective-step\\s+(\\{[\\s\\S]*?\\})\\s*-->"],
        "in": [
          "comment",
          { "comment": { "excludes": "^\\s*draft\\b" }, "regex": ["^dd:\\s*([\\s\\S]*)$", "^doc-detective:\\s*([\\s\\S]*)$"] },
          { "codeBlock": "dd" },
          { "codeBlock": { "language": ["doc-detective"], "metaExcludes": "\\bdraft\\b", "excludes": "^\\s*$" } },
          { "link": { "url": "^#dd$", "attributes": { "class": "^dd$" }, "precededBy": "^\\s*$", "excludes": "\\S" }, "value": "title" },
          { "image": { "src": "^#dd$", "attributes": { "class": "^dd$" }, "precededBy": "^\\s*$", "excludes": "^\\s*$" } },
          { "strong": { "precededBy": "\\bTest:\\s*$", "excludes": "^\\s*$" } },
          { "emphasis": { "precededBy": "\\bTest:\\s*$", "excludes": "^\\s*$" } },
          { "text": { "excludes": "^(?!\\s*Test step:)" }, "regex": "^\\s*Test step:\\s*(step\\b[\\s\\S]*)$" },
          { "element": "dd-statement" },
          { "element": { "tag": ["span"], "precededBy": "^\\s*$", "excludes": "\\S" }, "value": "attributes.data-dd" }
        ]
      },
      "markup": [
        { "name": "runCode", "codeBlock": "bash", "actions": ["runShell"] },
        {
          "name": "runShellUnlessNoRun",
          "codeBlock": { "language": ["sh", "shell"], "metaExcludes": "\\bno-run\\b" },
          "actions": ["runShell"]
        },
        { "name": "findOnscreenText", "strong": { "excludes": "^(?:step|test)\\b" }, "actions": ["find"] }
      ]
    },
    "asciidoc",
    "html",
    "dita",
    "rst"
  ]
}
```

This example uses every container at once so you can compare them. A real project picks the one or two its pipeline keeps.

### What detection finds

| Markup in `detected.md` | Read by | Step |
|---|---|---|
| A `bash` code block | `runCode` markup, replaced | `runShell` the block |
| A `dd` code block | `{ "codeBlock": "dd" }` | `goTo` |
| `[](#dd '…'){.dd}`, a link with no text | `link` container, `value: "title"` | `find` |
| `![…](#dd){.dd}`, an image | `image` container, the alt text | `click` |
| `<dd-statement>…</dd-statement>` | `{ "element": "dd-statement" }` | `type` |
| `<span data-dd='…'></span>` | `element` container, `value: "attributes.data-dd"` | `wait` |
| `Test step: step {…}` | `text` container with `regex` | `find` |
| `Test: **step {…}**` | `strong` container | `find` with `selector` and `elementText` |
| `Test: _step {…}_` | `emphasis` container | `checkLink` |
| `<!-- dd: step {…} -->` | `comment` container with `regex` | `find` |
| A `doc-detective` code block | `codeBlock` container with `language` | `find` |
| A `doc-detective draft` code block | None. `metaExcludes` skips it | None |
| `<!-- dd-step {…} -->` and `<!-- doc-detective-step {…} -->` | `step` patterns | `find` |
| A `dd` code block between `dd-skip` and `doc-detective-resume` | None. The ignore patterns skip it | None |
| An `sh no-run` code block | None. `metaExcludes` skips it | None |

- Each regex statement key lists two patterns, one for the older `dd-` keywords and one for the newer `doc-detective-` keywords. Files that use either work while a project moves between them. An ignored section can start with one keyword and end with the other.
- A container's `value` names the field that holds the statement. Without `value`, the statement is the node's main text: a code block's content, an image's alt text, or an element's content.
- A container's options narrow it like a selector's do. `precededBy: "^\\s*$"` takes only a node that starts its block. `excludes: "\\S"` takes only a link or `<span>` with no visible text. `"class": "^dd$"` takes only markup with the `dd` class, which the site can hide.
- The text container's `excludes` skips every prose run that doesn't start with `Test step:`, and its `regex` keeps the statement after the label.
- The replaced `findOnscreenText` skips bold text that starts with `step` or `test`, so the bold statement doesn't also become a `find` of its own text.
- `"comment"` as a string reads every comment. The built-in Markdown file type has it too. The inline variant's plain `test` comments therefore work with this config and with the default one.
- The `bash` definition's `name` is `runCode`, so it replaces the built-in `runCode` definition. A `bash` block then runs as a `runShell` step and isn't marked `unsafe`.
- This example is Markdown only. MDX reads `{.dd}` as a JavaScript expression, so it needs JSX attributes instead, and the other formats write links, images, and elements their own ways.
