## Fields

Validation applies the defaults shown here.

Field | Type | Description | Default
:-- | :-- | :-- | :--
headers | object([Response headers](/reference/schemas/response-headers)) | Optional. Headers expected in the response, in key/value format. If one or more `response.headers` entries aren't present in the response, the step fails. | ``{}``
body | one of:<br/>- object([Response body object](/reference/schemas/response-body-object))<br/>- array of unknown<br/>- string | Optional. JSON object expected in the response. If one or more key/value pairs aren't present in the response, the step fails. Omit it to skip the body check. | —
required | array of string | Optional. Array of field paths that must exist in the response body. Uses dot notation for nested fields (e.g., 'user.name') and bracket notation for array indices (e.g., 'items[0].id'). Fields must be present but may have any value including null. | ``[]``
schema | object | Optional. JSON Schema the response body must match. Checks types, formats (such as `uuid`, `email`, or `date-time`), patterns, and any other JSON Schema keyword, including exact values with `const` or `enum`. If set, it's used instead of the OpenAPI response schema. If omitted, the response is checked against the OpenAPI operation's response schema when `openApi.validateAgainstSchema` is `response` or `both` and the operation defines one, and isn't schema-checked otherwise. | —
